# 0002. Избор на база данни за Упражнение 4

**Status / Статус:** Accepted

## Context / Контекст

Notes API съхранява бележките в паметта по подразбиране и ги губи при рестартиране. За Упражнение 4 е необходимо постоянно съхранение на бележките и проверка за достъпност на хранилището чрез `GET /ready`. Приложението вече поддържа настройката `DATABASE_URL` и имплементация за PostgreSQL.

## Options / Варианти

1. **PostgreSQL**
   - **Плюсове:** постоянни данни, транзакции, съществуваща поддръжка в `app/repository.py`, подходяща среда за бъдещо контейнеризиране.
   - **Минуси:** изисква стартиране, конфигурация и поддръжка на отделна база данни.
2. **In-memory хранилище**
   - **Плюсове:** работи без допълнителна инфраструктура и е удобно за бързи тестове.
   - **Минуси:** данните се губят при рестарт и не покрива целта за постоянно съхранение.
3. **SQLite**
   - **Плюсове:** малка конфигурация и локален файл.
   - **Минуси:** би изисквала нова реализация на хранилището; липсва такава в текущото приложение.

## Decision / Решение

За Упражнение 4 избираме **PostgreSQL** и конфигурираме свързването чрез `DATABASE_URL`. При локални тестове без зададен `DATABASE_URL` запазваме възможността за работа в паметта.

## Consequences / Последствия

- При използване на PostgreSQL данните могат да се запазват между рестартиранията.
- Необходимо е да се осигури достъпна база и безопасно управление на данните за връзка.
- При недостъпна база `GET /ready` връща HTTP 503; операциите върху бележките също зависят от връзката.
- Решението е приложено чрез Docker Compose с PostgreSQL 17, именуван volume и healthcheck.
